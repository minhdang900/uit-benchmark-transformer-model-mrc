## 1. Tổng quan (Overview)

Bộ dữ liệu stress-test này được thiết kế để kiểm thử độ bền (robustness) và khả năng phân tích sâu (deep error analysis) của các mô hình Transformer trên bài toán Extractive MRC tiếng Việt. ## 2. Chi tiết từng danh mục (Category Details)

### 2.1 Negative & Trap Questions (Câu hỏi phủ định / bẫy logic)

**Mục tiêu lỗi (E3):** Lỗi phủ định / bẫy logic (~18% tổng lỗi)

**Đặc điểm:**
- Câu hỏi chứa từ phủ định (không, chưa, chẳng, ...) hoặc các câu hỏi "bẫy" (trap) dường như trả lời được nhưng thực chất không có thông tin trong ngữ cảnh.
- Mô hình thường nhầm lẫn và trích xuất câu trả lời từ đoạn văn bản nhiễu thay vì trả lời "không có thông tin".
- Bao gồm cả câu hỏi về sự kiện không tồn tại, thực thể không có trong ngữ cảnh.

**Ví dụ mẫu:**
```json
{
  "question": "Tại sao Boeing 787 không được đề cập trong đoạn trên?",
  "is_impossible": true,
  "plausible_answers": {"text": ["Không có thông tin về Boeing 787"], "answer_start": [-1]}
}
```

**Ngữ cảnh sử dụng:** 5 ngữ cảnh cốt lõi về di sản văn hóa, lịch sử Đảng, kinh tế, cây cầu, thể thao Việt Nam.

### 2.2 Multi-hop Reasoning (Câu hỏi suy luận bắc cầu)

**Mục tiêu lỗi (E4):** Lỗi suy luận bắc cầu & đồng nghĩa (~10% tổng lỗi)

**Đặc điểm:**
- Yêu cầu tích hợp 2+ thông tin từ các phần khác nhau của ngữ cảnh.
- Mô hình cần kết nối các mảnh thông tin rời rắt để đưa ra câu trả lời.
- Bao gồm câu hỏi so sánh, liên hệ nguyên nhân-kết quả, suy luỵ luỵ kết quả.

**Ví dụ mẫu:**
```json
{
  "question": "TP.HCM đóng góp bao nhiêu % GDP và có dân số bao nhiêu người?",
  "answers": {"text": ["khoảng 27% GDP và khoảng 9 triệu người"], "answer_start": [223]},
  "is_impossible": false
}
```

### 2.3 Compound Word Boundary Errors (Lỗi ranh giới từ ghép)

**Mục tiêu lỗi (E1):** Lỗi lệch ranh giới từ vựng (~42% tổng lỗi)

**Đặc điểm:**
- Tập trung vào các từ ghép tiếng Việt phức tạp: "Đại học", "Thành phố Hồ Chí Minh", "Cộng hòa Xã hội chủ nghĩa Việt Nam", ...
- Tokenization sai ranh giới từ có thể dẫn đến việc trích xuất câu trả lời thiếu hoặc sai phần.
- Kiểm thử khả năng giữ nguyên các từ ghép trong quá trình phân tích ngôn ngữ tự nhiên.

**Ví dụ mẫu:**
```json
{
  "question": "Tại sao 'Đại học Quốc gia Thành phố Hồ Chí Minh' trong đoạn văn trên lại là một từ ghép phức tạp?",
  "answers": {"text": ["Đại học Quốc gia Thành phố Hồ Chí Minh"], "answer_start": [85]},
  "is_impossible": false
}
```

### 2.4 Distractor Contexts (Ngữ cảnh dài với thực thể nhiễu)

**Mục tiêu lỗi (E2):** Lỗi ngữ cảnh dài / quá tải độ dài ngữ nghĩa (~25% tổng lỗi)

**Đặc điểm:**
- Sử dụng ngữ cảnh dài hơn 200 từ, chứa nhiều thực thể (tên địa điểm, tên người, số liệu...) phân tán.
- Mô hình phải lọc thông tin nhiễu để tìm câu trả lời đúng.
- Kiểm thử khả năng tập trung của mô hình khi đối mặt với thông tin dẫn dắt sai lệch.

**Ví dụ mẫu:**
```json
{
  "question": "Đại học Quốc gia Thành phố Hồ Chí Minh được thành lập năm nào?",
  "answers": {"text": ["2009"], "answer_start": [132]},
  "is_impossible": false,
  "context_length": 275  // >256 từ
}
```

### 2.5 Ambiguous Ground Truth (Nhãn gán mập mờ / trùng chứng)

**Mục tiêu lỗi (E5):** Lỗi nhãn gán mập mờ (~5% tổng lỗi)

**Đặc điểm:**
- Câu hỏi có thể có nhiều câu trả lời hợp lệ khác nhau (được chấp nhận).
- Mô hình đưa ra câu trả lời đúng về nghĩa nhưng không khớp xâu chính xác với ground truth.
- Kiểm thử khả năng đánh giá mềm (semantic matching) thay vì so khớp xâu tĩnh.

**Ví dụ mẫu:**
```json
{
  "question": "TP.HCM có dân số bao nhiêu?",
  "answers": {"text": ["khoảng 9 triệu", "9 triệu", "9.000.000"], "answer_start": [187, 187, 187]},
  "is_impossible": false,
  "note": "Multiple valid answer variants accepted"
}
```

## 3. Cơ chế kiểm tra Data Leakage (Automatic Data Leakage Detection)

### 3.1 Các cơ chế phát hiện rò rỉ

Module `src/data_leakage_checker.py` triển khai 5 cơ chế kiểm tra tự động:

| # | Cơ chế | Mô tả |
|---|--------|-------|
| 1 | **Context Overlap** | Kiểm tra xem cùng một chuỗi ngữ cảnh có xuất hiện ở nhiều split không |
| 2 | **Title Overlap** | Kiểm tra xem cùng một tiêu đề Wikipedia có xuất hiện ở nhiều split không |
| 3 | **ID Overlap** | Kiểm tra xem cùng một ID cặp câu hỏi-câu trả lời có xuất hiện ở nhiều split không |
| 4 | **Near-duplicate Contexts** | Dùng MinHash LSH để phát hiện ngữ cảnh gần như trùng lặp (paraphrased) |
| 5 | **Answer Leakage** | Phát hiện câu trả lời trùng lặp/ít nhất giữa các split khác nhau |

### 3.2 Kết quả kiểm tra leak on stress-test dataset

```
DATA LEAKAGE REPORT
======================================================================
Total contexts analyzed: 5
Total questions analyzed: 250
Severity: clean
Status: CLEAN

  Exact context overlaps: 0
  Title overlaps: 0
  ID overlaps: 0
  Near-duplicate context pairs: 0
  Answer leakage cases: 0
======================================================================
```

### 3.3 Hàm tiện ích cho pipeline huấn luyện

Hai hàm mới được thêm vào `data_leakage_checker.py`:

1. **`run_leakage_check_and_report(dataset_dict, output_path, fail_on_leakage)`**
   - Chạy tất cả kiểm tra rò rỉ
   - Lưu bá cáo JSON nếu có `output_path`
   - Ném `RuntimeError` nếu `fail_on_leakage=True` và phát hiện rò rỉ

2. **`assert_no_leakage(dataset_dict)`**
   - Wrapper tiện lợi cho việc sử dụng trong script huấn luyện
   - Tự động gọi `run_leakage_check_and_report` với `fail_on_leakage=True`

**Sử dụng trong pipeline:**
```python
from data_leakage_checker import assert_no_leakage

# Run before training
assert_no_leakage(train_val_test_datasets)
```

## 4. Cập nhật trong `dataset_loader.py`

### 4.1 Hàm mới

1. **`load_stress_test_dataset(categories, data_dir)`**
   - Tải toàn bộ stress-test data (hoặc danh mục cụ thể) dưới dạng `DatasetDict`
   - Tự động áp dụng context-level splitting để đảm bảo không có rò rỉ

2. **`_split_examples_by_context(examples, ...)`**
   - Hàm nội bộ: chia dữ liệu theo cấp độ ngữ cảnh (context-level)
   - Đảm bảo context không xuất hiện ở nhiều split

3. **`run_leakage_check(dataset_dict)`**
   - Wrapper gọn gọn để chạy kiểm tra rò rỉ và trả về dict kết quả

### 4.2 Cải tiến trong `load_multi_source_datasets()`

- Stress-test data giờ được phân bổ **đều across 3 splits** (train/val/test) thay vì chỉ val/test
- Tỷ lệ phân bổ: 60% train, 20% val, 20% test (dựa trên context-level splitting)
- Log chi tiết từng danh mục khi tải

## 5. Hướng dẫn sử dụng (Usage)

### 5.1 Tạo bộ dữ liệu stress-test

```bash
cd 02_CS221_DoAn_NLP_Benchmark
python src/stress_test_generator.py
```

Output:
- 5 file JSON danh mục riêng lẻ trong `data/stress_test/`
- File `stress_test_combined.json` (250 mẫu)
- File `leakage_check_report.json`

### 5.2 Tải stress-test dataset

```python
from dataset_loader import load_stress_test_dataset, run_leakage_check, get_split_summary

stress_ds = load_stress_test_dataset()
print(get_split_summary(stress_ds))
```

### 5.3 Chạy kiểm tra rò rỉ

```python
from data_leakage_checker import run_leakage_check_and_report, assert_no_leakage

# Kiểm tra và lưu báo cáo
report = run_leakage_check_and_report(dataset_dict, "leakage_report.json")

# Hoặc hard-assert trong pipeline huấn luyện
assert_no_leakage(dataset_dict)
```

### 5.4 Tải dữ liệu đa nguồn kết hợp

```python
from dataset_loader import load_multi_source_datasets

datasets, tokenizer = load_multi_source_datasets(
    model_name="vinai/phobert-base-v2",
    include_stress_test=True,
    use_context_split=True,
```
